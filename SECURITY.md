# Безопасность mMail

## Поддерживаемые версии

Исправления безопасности выходят для последней версии. Текущая ветка — `0.1.15`; более старые
сборки могут содержать известные проблемы зависимостей, поэтому обновляйте пакет.

## Как сообщить о проблеме

Пожалуйста, не публикуйте детали уязвимости в обычном issue. Используйте приватное сообщение
GitHub Security Advisory в репозитории:

<https://github.com/minlebay/mMail/security/advisories/new>

Приложите версию mMail, шаги воспроизведения и, если возможно, минимальное письмо/файл.

## Модель угроз

**Письмо — недоверенные данные.** HTML письма очищается ammonia, показывается в отдельном
WebKit-контексте без JavaScript, с CSP и запретом навигации. Внешние картинки загружаются
только по кнопке или для доверенного отправителя с `dmarc=pass`; загрузка идёт из ядра,
без cookies/Referer и с запретом локальной сети. Ссылки открываются только после подтверждения.

**Сеть.** IMAP и SMTP используют TLS 1.2+ с проверкой сертификата. Google OAuth — PKCE и
одноразовый loopback-приёмник. Ядро не принимает произвольные URL из интерфейса: открыть
можно только ссылку, которую пользователь подтвердил.

**Диск.** Пароли и ключи Google лежат в KWallet, кэш писем зашифрован SQLCipher, каталоги и
файлы доступны только владельцу. В `config.json` секретов нет.

**Локальные процессы.** mMail — настольное приложение без собственной песочницы. Процесс,
запущенный от того же пользователя, в принципе может прочитать его файлы, обратиться к KWallet
и выполнить команды `mmail` (они открывают кэш только на чтение). D-Bus-имя single-instance
тоже находится в сессии пользователя. Поэтому не запускайте недоверенный код от имени
пользователя, который читает почту. Для изоляции используйте отдельного пользователя или
песочницу ОС.

**Окна.** Главное окно читает почту; окно настроек не имеет команд чтения писем; окно ответа
получает только цитируемое письмо. Права окон перечислены в `src-tauri/capabilities/`.

**Dev-режим.** `npm run app` поднимает Vite на `127.0.0.1:1420` без аутентификации; в debug-
сборке приложение доверяет этому origin. Не используйте dev-режим на многопользовательской
машине; production-сборка (`tauri build`) загружает только встроенные ресурсы.

## Что не является границей безопасности

- Другой процесс того же пользователя (см. выше).
- Компрометация KWallet или сессии D-Bus.
- Уязвимость в системном WebKitGTK: очистка HTML снижает поверхность, но не заменяет
  обновление системы.
- Почтовая программа получателя: mMail не отвечает за то, как чужой клиент отрисует письмо.

## Для разработчиков

- `cargo audit` и `npm audit` должны быть чистыми; обновляйте `Cargo.lock` при выходе
  security-релизов.
- Не добавляйте окнам права `shell`, `fs`, `http`, `opener`, если это не абсолютно необходимо.
- Новые внешние ресурсы (картинки, CSS, шрифты) должны проходить через ядро и CSP, а не
  загружаться из документа письма.
- Текст из письма и от сервера перед выводом в терминал/логи проходит через `text::console_safe`,
  перед показом в интерфейсе — через `text::display_safe`.
- Тесты: `cargo test` в `src-tauri/`, `npm test` в корне. `tests/security.test.js` проверяет CSP,
  capabilities и отсутствие секретов в git.
